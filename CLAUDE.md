# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Krya ("Your language. Your shortcut."; called Altype until 0.11 (2026-10-30), 2Talker until 0.3, tu-talk before that): a Windows tray app (Electron) that translates a picked text offline and reads the English aloud; it also translates any text both ways like DeepL, reads text from the screen, and switches and fixes keyboard layouts (in place of EveryLang). A sibling of the Language Tutor in `ikstro/cc-translator` (`E:\Cursor\Plugin\CC-translator`): the card's webview, the natural voice, the system voice and the word dictionary were copied from its `panel/` and adapted; the two repositories do not share code at build time.

## Commands

```
npm install
npm test                          # vitest
npx vitest run src/translate.test.ts
npm run typecheck
npm run build                     # esbuild: dist/main.js, preload.js, mt-worker.js, voice-worker.js, kbd-worker.js, field-worker.js; media/card.js, app.js, tray.js; codicons into media/
npm start                         # build + electron .
npm run dist                      # electron-builder → release/2Talker-Setup-<version>.exe (NSIS, win-x64)
npm run icons                     # Krya's icon K3, the duck {•> on a black tile, white braces and eye, a yellow beak (build/icon.svg's shapes, drawn on a canvas under Electron) → build/icon.png (512), build/icon.ico (16–256; 16 set pixel by pixel, the tile's corners too, `TILE_16`), media/icon.png (128); the tray's T2 {•> for a light and a dark taskbar, each also paused (45 %), and the red record dot → media/tray-{light,dark}[-paused].png, tray-recording.png, each with @2x (16 set pixel by pixel, 32 the same pixels doubled; the dot drawn on its own 32 grid)
npm run models                    # scripts/build-mt.mjs: src/mt-manifest.json + vendor/bergamot from Mozilla
npm run glyphs                    # scripts/build-glyphs.mjs: the Lucide icons the pages use (lucide-static, MIT) → src/webview/lucide.ts
npm run shots                     # scripts/shots.mjs: every page, the tray panel and the badge pictured offscreen → .cache/shots/*.png (build first; runs beside the installed Krya)
node scripts/build-words.mjs      # media/layout/{en,ru,uk,bg,mk,el,he,ar,fa,ka}.txt: the layout fixer's word lists (FrequencyWords; it has no be, kk, hy, and its sr is Latin)
cd engine; uv sync --extra speakers-gpu --group dev   # the speech engine for development, in engine/.venv
npm run test:engine               # engine/tests in engine/.venv (uv run --no-sync); the release workflow runs it on the core part
```

One Krya at a time, always: `main.ts` takes the single-instance lock on Krya's own folder before anything else, so a second start (installed, `npm start` or a test run) hands its arguments to the first and quits; an Altype still running (an older install, whose lock is on its own folder) is named in a message and Krya quits (`oldAppRunning`), as its folders are about to move. A test run (`KRYA_TEST_HOME=<folder>`: its own settings and speech engine folder, `KRYA_TEST_PORT`, 8797 by default, Windows' startup list left alone, nothing moved from the old folders; the `ALTYPE_*` names still read) therefore needs the installed Krya quit first.

Uninstall (`build/installer.nsh`, `customUnInstall`) asks once whether the data goes too: Yes removes `%APPDATA%\Krya` (and `Altype`, `2Talker`, `tu-talk`), `%LOCALAPPDATA%\Krya` (the speech engine; and `Altype`) and `Documents\Krya` (transcripts; and `Altype`); No keeps everything for a later install; an update (`--updated`) and a silent uninstall never ask or delete; notes in the knowledge base are never touched.

Release: bump `version` in package.json, commit, tag `v<version>`, push the tag. `esbuild.mjs` stamps the main bundle with `KRYA_BUILD` (time, git commit, changed); About, Settings › Version and the tray show the version, and a run from source says "dev" and when it was built (`buildText`), so it is never taken for the last release. `.github/workflows/release.yml` builds and tests on windows-latest with a read-only token (`npm run dist -- --publish never`), then a second job, which runs no npm or PyPI code, drafts the GitHub release with the installer (`gh release create --draft`, `--prerelease` for a tag with a dash); publishing the draft is the owner's step. Actions are pinned by commit, checkout keeps no credentials. Krya does not update itself (2026-10-30, the owner: "обновление только через GitHub"): electron-updater and `src/update.ts` are gone; Settings › Version and About link to the releases, and the installer installs over the old version. The installer is unsigned.

A shell started from VS Code or Claude Code may carry `ELECTRON_RUN_AS_NODE=1`; Electron then runs as plain Node and `electron.app` is undefined. Run with it unset (`env -u ELECTRON_RUN_AS_NODE …`).

## Architecture

Main process (`src/main.ts`): tray, the card window, the app window, flows. `%APPDATA%\Krya\`: `settings.json` (`settings.ts`), the person's lists and logs; `words.json` (`words.ts` `WordStore`: the notebook, one entry per dictionary form; `ankiTsv` for Anki's import); `adoptOldFolder` moves them over from `%APPDATA%\Altype` (and `2Talker`, `tu-talk`) once, item by item (`oldfolder.ts ITEMS`: the app's own files, never Electron's caches; `altype.log` becomes `krya.log`). **Everything downloaded is in one folder**, `%LOCALAPPDATA%\Krya` (never roamed): `models\<code>\` (Firefox's translator), `voice\` (Kokoro), `dict\`, `translate\`, `speech\`; it was `%LOCALAPPDATA%\Altype` until 0.11 and moves over at start, whole when Krya has none yet, else part by part (`adoptLocalFolder`); the speech engine's Python remembers its place by absolute paths (`env\pyvenv.cfg` `home`, the junction uv makes for the minor version in `python\`), which `repairSpeech` rewrites, so it runs as it was with no new install (its packages' hard links into uv's cache move with it; the launchers in `env\Scripts` keep the old path, never used); the first three lived in `%APPDATA%` until 0.10.1 and move over once at start (`oldfolder.ts moveDownloads`); a part that cannot move is used where it is (`partDir`, `localPart`, `downloads`; the engine is told its folder, `KRYA_SPEECH_DIR`); a program run from inside the old folder keeps its files in use (the speech engine's python.exe and uv.exe, llama-server.exe, left by Altype or a run from source), so while the old folder holds a part Krya's has not (`hasToMove`), those programs are stopped first (`freeFolder`: Windows' list through PowerShell `-EncodedCommand`, CIM `Win32_Process.ExecutablePath`, `holdersIn` picks those under the folder, never Krya or Altype.exe, which `oldAppRunning` waits for), and `krya.log` says what was stopped and what stayed and why (`leftIn`, `whyLeft`: "left in …\Altype: speech (a file in it is in use by python.exe)"; a part Krya has its own copy of stays, unused). The old names' updater downloads (`%LOCALAPPDATA%\altype-updater`) go. Closing the card (`hideCard`: Esc, ✕, a click elsewhere) also sends `stop` to the card, which plays the natural voice's audio itself. Esc and ✕ (`closeCard`, 2026-10-30) first give the keyboard back to the window in front when the card opened (`cameFrom`; a Translate card from a selection, its `pasteTarget` window and field, as Paste does), as a hidden card leaves Windows to bring up a window of its choosing; a click elsewhere only hides it.

- **Selected text**: `winclip.ts` registers the card window as a clipboard listener (user32 through koffi; `WM_CLIPBOARDUPDATE` via `hookWindowMessage`). `clipboard.ts` `DoubleCopy`: two changes 40–650 ms apart with Ctrl held = a request (`doubleCopy` setting); changes closer than 40 ms are one copy announced in several formats. Copies made inside the focused card are ignored. The selection shortcut (`selectKey`, none by default) waits until its keys are let go, presses Ctrl+C in the program in front (`pressCopy`, `keybd_event`) and takes the next clipboard change within 2 s (`COPY_WAIT_MS`, `copyWanted`; 600 ms until 0.10.1, too short for a busy VS Code, whose late copy was thrown away as "Nothing was copied"; `krya.log` says "copy: came in N ms from <exe>" or "copy: nothing in 2000 ms"; the fix key's `convertOver` waits as long). `registerShortcuts()` registers it and `snipKey`; either may be empty.
- **Screenshot**: the snip shortcut (`snipKey`, default Ctrl+Alt+S) opens `ms-screenclip:` (Windows' snipping overlay); the next picture on the clipboard within two minutes is the snip (`clipboard.read()`, `image/png`; Electron 45's clipboard API is async). `ocr.ts` runs `Windows.Media.Ocr` through Windows PowerShell (`-EncodedCommand`, never `-ExecutionPolicy`): every installed engine of the person's languages reads the snip (their own first, English last; small text, lines under 20 px, scaled up twice first: three times read worse), and `ocrpick.ts` `pickLines` takes each line from the reading that reads it best (`lineScore`: words in the person's lists count for it; Cyrillic or Greek look-alikes between Latin words, a bracket by a letter, mixed scripts against it), then its doubtful words from another reading where the line reads better (`mergeLine`). One engine is not enough (2026-10-29): the Russian one wrote English "can", "a", "gpu" as "сап", "а", "дри", which the direction rule then sent into English; `ocrtext.ts` joins lines into paragraphs by their boxes. Two purposes (`Purpose`), each from the selection or the screen: **listen** (the card above: `doubleCopy`, `selectKey`, `snipKey`) and **translate**, the translator (`translateKey` with `useSelection('translate')`, `textKey` with `snip('translate')` → `readScreenText`): the same card in kind `translate` or `text`, the text as it is (editable, its English words clickable), Copy, From ⇄ To over the 32 languages, translated at once (`translateWindow`, `translateTextCard`). `translate.ts` `languageOf` guesses the source (a script of one language; letters of one language: қ… kk, і/ї/є/ґ uk, ђ… sr, ы/э/ё ru, پ… fa; else the language with most of its 200 common words in the text, `media/lang-words.json`; a short text: English by `media/layout/en.txt`), the vote and the English rule only among the languages the person uses (`pool`: `settings.ts myLanguages`: their own, English and `languages`, chosen in Settings; a script none of them uses falls back to all 32), `targetFor` the target (the person's own, English from it), `translatePlain` translates through English when neither side is. No Translate button: an edit is translated again after a 700 ms pause (the last translation shown faded meanwhile), a language picked at once. Swap (framed, after the languages) swaps them and, a translation in, makes it the text (DeepL's way). Paste (blue; Enter on the window or in the field, Shift+Enter a new line; a translation still coming is pasted once in; only for a selection, `canPaste`): `pasteTranslation` brings back the window the text was selected in (`focusWindow`, `SetForegroundWindow` while the card is in front), hides the card and pastes over the selection through the clipboard. Nothing of Krya's is left on the clipboard (2026-10-29): every borrowing (the selection keys, Paste, Translate in place, the fix key over a selection, a dictated phrase, Chrome's address, the snip) goes through `clipguard.ts` `ClipboardGuard` over `winclipboard.ts` (user32 through koffi, the card's window owning the writes): `hold` keeps every format there (copied files and Office's formats too; GDI handles and private formats are not kept), one snapshot for a run of actions close together (the fix key pressed twice); Krya's writes and its putting back carry `ExcludeClipboardContentFromMonitorProcessing`, `CanIncludeInClipboardHistory` = 0 and `CanUploadToCloudClipboard` = 0, so Win+V and the cloud clipboard never see them; a text to paste is only promised (`writeText(…, paste)`, Windows' delayed rendering: `SetClipboardData` with no data, handed over in `WM_RENDERFORMAT` through the card window's hook, `watchRendering`), and `ClipboardGuard.read` decides who gets it: before Ctrl+V (`pasted`) nobody is pasting, so a program asking then is one watching the clipboard against the history marks and gets nothing (2026-10-30: Viber reads every change within a millisecond, which hid the paste's own read), after it the paste's program does, and that read is the signal; `release` puts it back `AFTER_READ_MS` (150) after it, `READ_WAIT_MS` (2.5 s) at most when no read is seen (a fixed 500 ms before let a slow program paste the old content), only while the clipboard's sequence number is still one of Krya's (`write`, `claim` for a copy Krya pressed) — a copy the person made meanwhile stays — and writes nothing when nothing changed; another program holding the clipboard is waited for; quitting puts back at once (`flush`, before the windows close). The listener skips Krya's own changes by their number. A selection key that finds nothing copied waits `LATE_COPY_MS` for a late copy (Ctrl up) to take back too; the snip puts back what was there once the picture is read, and a copy without a picture ends the wait for it (Ctrl+C twice works again at once). Windows' own snipping tool still puts its picture in Win+V. Ctrl+C twice is the person's own copy.
- **Translation**: `translate.ts` `pairText` splits lines into sentences (`sentences.ts`) and decides each sentence's direction by script (`directionOf`): the person's script → into English (English shown, original behind the tap), Latin → into their language. Same-script natives (German…) are treated as English source for now. `splitText` + `translateLines`: when no sentence goes into English (`englishReady`), `main.ts` `translateInto` shows the English at once (`done` with the translation `translating`/`downloading`) and the card starts reading while the translation comes. `render.ts` writes two halves as plain paragraphs, one per line (no markdown: a picked text is not markdown; `sentences.ts` `unwrapLines` first joins lines broken mid-sentence: a line ending in a letter, digit, comma or hyphen followed by one starting in lower case without a list marker; a list item goes on so too): `englishHtml` (`span.s[data-i]`) and `translationHtml` (`span.t[data-i]`).
- **Translator** (`engine.ts`, interface `translator.ts`): Firefox Translations (Bergamot, WebAssembly, `vendor/bergamot`, shipped). Models per pair from Mozilla's attachment CDN, pinned with size and SHA-256 in `src/mt-manifest.json`, stored as `<sha256 head>-<name>`. `scripts/build-mt.mjs` picks, per direction, the newest complete version whose filter expression passes for Windows release (en→ru 2.0; the nightly 2.1 invents words). The engine runs in a worker thread (`mt-worker.ts`, loader via `vm.compileFunction`, Firefox's decoder config), ended after 5 idle minutes.
- **Translation levels** (2026-10-29; one model for translation and checking since 2026-10-30, 0.10.2: `settings.translationLevel`: `fast` | `accurate` | `most`, `LEVEL_NAMES`, and `settings.model`: `accurate` | `most`, the one local model, which Check my English always uses; a model that cannot start on the card is started on the processor (`--device none`) until Krya restarts. The Translate page's **Translation** section: the three levels, the one in use lit, Use downloads it (with its progress), a cross removes a downloaded model, and **Recommended** from the card's own memory (`hardware.ts translationAdvice`, for checking too: the 12B on 9 GB, the E4B on 3.5 GB (its per-layer embeddings stay in the computer's memory), half of that partly on the card, else the processor, "possible, but slow here"), the model Check uses noted when the level is Fast ("Check my English uses it"); once a level has translated three times here, its line says the time measured instead of the guess ("here: 0.3 s a sentence, 3.0 s to load after 10 idle minutes", "slow here" over 2 s a sentence): `llmtranslator.ts onTimed` (a sentence from the server ready to done, the load when the job waited for it, `LlamaServer.run`'s `loaded`), `device.ts nextModelSpeed` keeps the latest 9 of each per model, a sentence, a text checked and the load, in `device.json` `models` (dropped with another computer's profile; 0.10.1's `translate.check` taken as Accurate's, TranslateGemma's times dropped), the median shown (`AppView.modelSpeed`), so a first run that prepares Vulkan's shaders does not decide. ## Product rules (owner decisions, 2026-10-29): translation levels

- Three levels, one setting for every card and key (on the Translate page): **Fast** (Firefox Translations, the default), **Accurate** (TranslateGemma 4B), **Most accurate** (TranslateGemma 12B). Firefox read a short instruction word by word ("Кнопки сундука и молнии поменять местами." → "The chest buttons and lightning change places."); the 2026-10-27 comparison of five local models found TranslateGemma clearly better.
- The person picks the level; nothing downloads before. Each level says Recommended or "possible, but slow here" for this computer.
- The card translates with the level picked and waits for it (its download the first time); it never falls back to Fast by itself.
- Krya runs the models itself (llama.cpp), not the speech engine's Python; their files live beside the speech engine in `%LOCALAPPDATA%\Krya`.
- llama.cpp's Vulkan build (37 MB) for everyone; its CUDA build (670 MB) only for NVIDIA cards, and only if it measures at least 1.5× quicker. Measured on the RTX 2080 SUPER with the 4B (2026-10-29): Vulkan 106 tokens a second, CUDA 105 (a short sentence 0.19 s against 0.15 s, a long text 1.9 s against 1.7 s), so the 4B runs on Vulkan; Vulkan loads the model in 7.5 s, CUDA in 3.1 s. The 12B, partly on that 8 GB card: Vulkan 2 tokens a second with `--fit` or every layer, 3–6 with 28 layers (a long text 77 s), CUDA with every layer 12 (20 s), so a model that does not fit an NVIDIA card runs on CUDA (+670 MB in its download). Krya's own code on that computer (`llmtranslator.ts` through `translatePairs`, four sentences at once): Accurate on Vulkan loads in 3 s, then two sentences 0.65 s, eight 2.6 s; Most accurate on CUDA loads in 7 s, then two sentences 2.5 s, eight 17 s. The first run on a computer is slower once: Vulkan prepares its shaders for each new batch size (up to 10 s), which NVIDIA's driver keeps for the next runs.
